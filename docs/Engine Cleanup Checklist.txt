Engine Cleanup Checklist
Purpose: short, agent-friendly cleanup and workflow tasks that improve day-to-day development.
Use this file when the question is "what small useful improvement should be done next?"

==================================================
1. Immediate Cleanup
==================================================

[ ] 1.1 Fix remaining hardcoded world-size assumptions
Goal:
- Remove old hardcoded startup assumptions like 200 or 400 world units.

Files:
- src/app/Main.cpp
- src/rendering/d3d11/D3D11Renderer.cpp
- any other files using hardcoded world/cell sizing

Steps:
- Replace remaining hardcoded startup cell coordinates with values derived from WorldGrid::GetCellSize()
- Search for "200.0f", "400.0f", and similar startup-size assumptions
- Convert reusable values into named constants or derived variables

Acceptance:
- World loads correctly with cell sizes 100, 200, and 400
- Spawn starts in the center of cell (0,0)
- Cell crossing still works

[ ] 1.2 Remove unused default entry files
Goal:
- Avoid confusion about which entry point is actually used.

Files:
- GameRewritten.cpp
- solution/project settings if needed

Steps:
- Confirm GameRewritten.cpp is not part of the actual runtime path
- Remove it from build or delete it if safe
- Make sure only the real game startup path remains obvious

Acceptance:
- There is one clear real application entry path
- No misleading Hello World stub remains in active build

[ ] 1.3 Clean D3D11Renderer shutdown/resource handling
Goal:
- Reduce duplicate cleanup code and prevent missed releases.

Files:
- src/rendering/d3d11/D3D11Renderer.cpp
- src/rendering/d3d11/D3D11Renderer.hpp

Steps:
- Add a safe COM release helper
- Release missing resources such as groundInputLayout if still missing
- Remove repeated Release/nullptr blocks where practical
- Keep behavior unchanged

Acceptance:
- Build succeeds
- Shutdown remains correct
- Cleanup code is shorter and easier to extend

==================================================
2. Main.cpp Reduction
==================================================

[ ] 2.1 Reduce responsibilities in Main.cpp
Goal:
- Make Main.cpp orchestration-only over time.

Files:
- src/app/Main.cpp
- new helper files/classes as needed

Steps:
- Move feature-specific logic out of Main.cpp in small steps
- Keep Main.cpp focused on:
  - startup
  - system wiring
  - per-frame high-level update
  - per-frame high-level draw
  - shutdown

Acceptance:
- Main.cpp becomes easier to scan
- New gameplay systems no longer default to being added directly to Main.cpp

[ ] 2.2 Introduce small runtime coordinators
Goal:
- Create obvious homes for code that currently lands in Main.cpp.

Suggested future classes:
- GameApp
- WorldRuntime
- PlayerActor
- RuntimeScene  <-- first pass done: src/game/RuntimeScene.hpp coordinates
                    per-frame runtime actor visual submission (player; add
                    enemies/NPCs here as they are implemented)

Acceptance:
- New engine systems have a clear location
- Main.cpp no longer owns detailed gameplay behavior

Files:
- src/game/PrimitiveRenderer.hpp
