# Quality Bar (What “Good Enough” Means Here)

## Required quality checks
- **Readability:** narrative flow, self-describing names.
- **Clarity:** ownership and purpose are obvious.
- **Compile safety:** no broken build path.
- **Behavior verification:** changed behavior tested/smoke-checked.
- **Small scope:** focused, reviewable change.
- **Doc alignment:** relevant docs updated if needed.
- **Performance awareness:** low-spec safety considered.
- **No fake completeness:** unfinished parts are labeled honestly.

## Merge readiness checklist
- [ ] Scope is focused.
- [ ] Code placement is correct.
- [ ] No unnecessary architecture expansion.
- [ ] Performance risk is controlled.
- [ ] Current vs target vs future is clearly labeled where needed.
