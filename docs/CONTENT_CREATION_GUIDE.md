# Content Creation Guide

This guide defines the required import workflow for getting new art/audio assets into runtime-safe `Content/` folders and registered for lookup.

See also:
- `docs/ASSET_PIPELINE.md`
- `docs/ASSET_REGISTRY.md`
- `tools/import_assets.py`

---

## 1) Import contract (what every asset must satisfy)

1. Source output is generated by one of the supported external tools:
   - Audio Engine
   - Animation Engine
   - Creation Engine
2. Imported files must end up under the correct `Content/` subfolder.
3. Imported files must be addressable through `Content/AssetRegistry.json` scoped IDs.
4. Asset IDs and paths must be stable and deterministic (no ad-hoc naming).

---

## 2) Required folder targets by asset type

| Asset type | Required destination |
|---|---|
| Audio (`.wav`, `.ogg`, `.mp3`, `.flac`) | `Content/Audio/` |
| Animation (`.anim`, `.gltf`, `.bin`) | `Content/Animations/` |
| Textures (`*_albedo.png`, `*_normal.png`, etc.) | `Content/Textures/` |
| Meshes (`.obj`, `.mtl`) | `Content/Models/` |
| Material-like JSON (`textures` + `params`) | `Content/Materials/*.material.json` |
| World tilemap JSON (`tiles`) | `Content/World/` |
| Other Creation JSON manifests | `Content/Bundles/` |

---

## 3) Standard import workflow (required)

Use `tools/import_assets.py` first. It is the primary supported importer.
Run these commands from the repository root.

### Audio import
```bash
python tools/import_assets.py \
  --engine audio \
  --src /absolute/path/to/audio_export
```

### Animation import
```bash
python tools/import_assets.py \
  --engine animation \
  --src /absolute/path/to/anim_export
```

### Creation import
```bash
python tools/import_assets.py \
  --engine creation \
  --src /absolute/path/to/creation_export
```

### Dry-run safety pass (recommended before large imports)
```bash
python tools/import_assets.py \
  --engine creation \
  --src /absolute/path/to/creation_export \
  --dry-run
```

---

## 4) Import behavior details you must rely on

- Source subdirectories are preserved in destination paths.
- Asset registry entries are added/updated automatically after successful import.
- Registry key collisions are auto-disambiguated deterministically.
- Creation manifests can drive routing with `content_target` when present.
- `.obj` and `.mtl` are routed together to `Content/Models/` so relative material links resolve.
- Material-like manifests are emitted to `Content/Materials/` as `*.material.json`.

---

## 5) AssetRegistry usage rules

1. Runtime lookups use scoped IDs (example: `textures.grassland`, `audio.bgm_field`).
2. IDs should be lower-case and stable.
3. Always verify imported assets have correct `Content/...` path prefixes.
4. Do not hardcode new absolute file paths in gameplay code; use scoped IDs.
5. If manual edits are required, keep JSON valid and maintain existing structure.

---

## 6) Manual import fallback (only when needed)

Use manual copy only when the importer cannot process a source set yet.

1. Copy files into the required `Content/` destination from Section 2.
2. Add corresponding scoped IDs to `Content/AssetRegistry.json`.
3. Verify each path exists and starts with `Content/`.
4. Run runtime reload path (where available) and confirm lookups resolve.

---

## 7) Acceptance checklist before marking assets done

- [ ] All imported files are in the correct `Content/` subfolders.
- [ ] `Content/AssetRegistry.json` contains IDs for all required runtime-referenced assets.
- [ ] No duplicate/ambiguous IDs were introduced without deterministic suffixing.
- [ ] Creation mesh pairs (`.obj`/`.mtl`) stay together.
- [ ] Material manifests resolve to `Content/Materials/*.material.json`.
- [ ] Import command output shows expected copy operations (or dry-run preview is clean).

---

## 8) Publish flow (authoring to runtime)

1. Export from source engine.
2. Dry-run import for validation.
3. Perform real import with `tools/import_assets.py`.
4. Spot-check `Content/AssetRegistry.json` additions.
5. Launch runtime/editor and validate that loaded IDs resolve to expected content.
6. Commit imported assets + registry updates together.
